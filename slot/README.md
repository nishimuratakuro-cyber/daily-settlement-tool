# スロット立ち回り支援ツール

期待値ベースで立ち回るための計算ツール。勝てる台を当てにいくのではなく、
**「その台・その状況が期待値プラスか」「いまの収支は運の範囲内か」を数字で詰める**ためのもの。

## 機能

| ページ | 何をするか |
|---|---|
| 🎯 設定判別 | 小役・ボーナスの観測回数から、各設定の事後確率をベイズ推定。ホールの設定配分を事前分布として反映でき、期待機械割も出す |
| ⏱ 天井狙い | 現在ゲーム数からの期待差枚と、**期待値がプラスに転じる狙い目ライン**を計算 |
| 📐 シミュレーション | 差枚の分布をモンテカルロで生成。勝率・分位点・資金ショート確率を確認 |
| 💰 収支管理 | 実戦記録を集計し、ブートストラップ信頼区間で「勝ちと言い切れるか」を判定 |
| 🏠 ホール傾向分析 | 店舗×日付×台番の実績から、**どの店の・どの日に・どの機種へ設定を使っているか**を推定 |
| 🧮 手順チェック | 「この手順で機械割○%over」という主張を、**1台あたりの実額・実効時給・交換率別の損益分岐**に変換して検証 |

## 使い方

```bash
pip install -r requirements.txt
streamlit run slot/app.py
```

テストは追加の依存なしで動く（標準ライブラリのみ）：

```bash
python3 -m unittest discover -s slot/tests -p "test_*.py"
```

## データの用意

### 機種テーブル（設定判別用）

`data/machines_sample.csv` と同じ書式の CSV を用意してアップロードする。

```csv
機種,事象,種別,設定1,設定2,設定3,設定4,設定5,設定6
機種名,BIG,確率,1/273.1,1/270.8,1/266.4,1/254.0,1/240.9,1/219.9
機種名,ぶどう,確率,1/6.35,1/6.35,1/6.29,1/6.21,1/6.16,1/5.92
機種名,機械割,機械割,97.0,98.2,99.5,101.5,103.8,106.0
```

- 確率は `1/273.1` でも `273.1` でも `0.00366` でも読める
- 空欄の事象は判別に使われない（解析値が未公開の役はそのままでよい）
- 設定列は 6 段階でなくてもよい（2 列以上あれば動く）

同梱ファイル:

| ファイル | 内容 |
|---|---|
| `machines_sample.csv` | **ダミー値**。書式の見本 |
| `machines_myjuggler5.csv` | **実データ**（マイジャグラーV）。設定1・3・5・6の BIG / REG / ぶどう |

`machines_myjuggler5.csv` は設定2・4 の個別確率が確認できなかったため列を持たせていない
（設定列は 2 つ以上あれば何列でも動く）。行くホールが設定2・4 を使うなら、解析サイトで
値を確認して列を追加すること。機械割の行も確認が取れていないので入れていない。

それ以外の機種は自分で用意する。解析値を同梱しないのは、機種ごとに値が違ううえ
改訂もされるため。

### ホールデータ（ホール傾向分析用）

必須列は **日付 / 総回転数 / 差枚** の 3 つだけ。列名のゆらぎは自動で吸収する
（`営業日`→日付、`G数`→総回転数、`差枚数`→差枚、`台番号`→台番、など）。
`▲1,200` や `(1200)` のような会計式のマイナス表記もそのまま読める。

```csv
営業日,店舗名,台番号,機種名,総回転数,差枚,BB回数,RB回数
2026-09-07,Aホール,101,サンプルAT機,5820,3140,22,15
```

データを集めるときの優先順位:

**Aタイプ（ジャグラー等）の島を優先して集めること。** 1台1日で測れる機械割の標準誤差は
Aタイプが約5.7pt、AT機が約18.7pt で、**分散に約11倍の差**がある。ボーナスの獲得枚数が
小さいぶんAタイプのほうが結果が安定するため、同じ精度を得るのに必要な台数が約1/11で済む。

| 対象 | 台数 | 1日で測れる出玉率の精度 |
|---|---|---|
| ジャグラー島のみ | 60台 | **±1.44pt** |
| Aタイプ島 全体 | 120台 | **±1.02pt** |
| AT機 全体 | 200台 | ±2.59pt |
| 店全体 | 320台 | ±1.51pt |

AT機だけを見ると1日では店の傾向を判定できないが、**Aタイプ島なら60台で1日でも判定できる**。

集計の考え方:

- **機械割は台ごとの平均ではなく加重値**（総差枚 ÷ 総投入）。300G で +600枚 のような
  短時間の台に平均を壊させないため
- **高設定率**は 2000G 以上回った台のうち機械割 105% 以上だった割合
- 店舗別・日付パターン別の差は**ブートストラップ信頼区間**付きで出すので、
  「たまたま出ただけの日」と「実際に使っている日」を切り分けられる

> **データの入手について**: このモジュールは通信を一切行わない。データサイトの多くは
> 規約で自動抽出（スクレイピング）を禁止しており、技術的な対策やペナルティもある。
> 自分が正規に閲覧できる画面から手元にエクスポート／記録したファイルを読み込む前提で設計している。

### 収支記録

`data/ledger_sample.csv` の列構成に合わせる。必須は `日付` のみ。
`収支` 列が無ければ `回収額 - 投資額` で自動計算される。

## 立ち回り情報の読み方（手順チェックの背景）

SNS で流れてくる「リセ狩り手順・機械割○%over」を鵜呑みにしないための換算式。

```
期待差枚(枚)  = 3 × 消化G × (機械割 − 1)
名目時給(円)  = 3枚 × 600G/h × (機械割−1) × 20円 = 36,000 × (機械割 − 1)
EV(円)        = 換金単価 × E[差枚] − (貸出単価 − 換金単価) × E[負け枚数]
```

- **機械割の小数点以下を36,000倍すると時給になる**（等価・600G/h）。102% は時給720円
- **率が高くても消化が短ければ実額は小さい**。107% を41Gだけこなす手順の実額は +172円
- **現金投資・非等価では損益分岐が100%を超える**。5.6枚交換で1Gあたり負け2枚なら108%。
  メダルは循環するので現金で買うのは負けた分だけだが、負けは貸出単価・勝ちは換金単価という
  非対称性が残るため。貯メダル／持ちメダル遊技なら100%に戻る
- **台探し・移動・判別の時間**を入れると実効時給は大きく下がる。1台4分の手順に付帯6分が付けば
  時給は 2,580円 → 1,032円

## モデルの前提と限界

- **設定判別**: 各事象を独立な二項試行として扱う近似。実際の小役は排反なので厳密には
  多項分布だが、実用差は小さい
- **天井狙い**: `ceiling_ev` は通常時のハザードを一定とみなす閉じた式。**ゾーンが効く機種では
  この近似が大きくずれるので `hazard_ceiling_ev` を使う**（下記）
- **資金ショート確率**: 終了時点の必要現金が資金を超えた割合。途中経過はさらに沈むため、
  実際の破産確率はこれより高い
- **非等価**: 勝ち分は換金単価、負け分は貸出単価で評価している。このため差枚 ±0 でも
  現金収支はマイナスになる（＝機械割 100% では勝てない）
- **ホール傾向**: 差枚から逆算した機械割は「結果」であって設定そのものではない。
  客の打ち方（天井到達まで回したか、早めにやめたか）でも動く

## ハザード一定近似のズレ（天井狙いで重要）

`ceiling_ev` は「通常時の当選確率が一定」という仮定の閉じた式で、ゾーンの無い機種なら
正確（厳密計算と 1e-11 まで一致することをテストで確認済み）。しかし**天国やゾーンのある
機種では大きくずれる**。

天井800G・当選率1/400相当・天国32Gが20倍・100G刻みのゾーンが10倍（全体の当選率は
一定版に揃えて校正）で比較した結果:

| 開始G | 一定近似の期待差枚 | ゾーン考慮（厳密） | ズレ |
|---|---|---|---|
| 0G | −51.5枚 | **+210.8枚** | **+262.3枚** |
| 100G | −9.3枚 | **−173.5枚** | **−164.2枚** |
| 300G | +114.7枚 | +30.7枚 | −83.9枚 |
| 500G | +319.1枚 | +304.6枚 | −14.5枚 |
| 700G | +656.4枚 | +671.8枚 | +15.4枚 |

**ズレは大きいうえ、開始ゲーム数によって符号が反転する。** 当選が前方に寄る機種では、
浅いゲーム数の期待値を過小評価し、ゾーンを通過した直後は過大評価する。

実務上の影響が最も大きいのは狙い目ライン:

```
一定近似が示す狙い目   : 119G
ゾーン考慮の正しい狙い目 : 270G   ← 151G も浅い地点から打たせてしまう
```

### 使い方

```python
from slot_core.ev import (zone_hazard, calibrate_hazard, total_hit_probability,
                          hazard_ceiling_ev, hazard_breakeven_start_games)

# 全体の当選率を実機の値に合わせたまま、天国とゾーンの形を入れる
hazard = calibrate_hazard(
    lambda base: zone_hazard(base, heaven_games=32, heaven_multiplier=20,
                             zone_every=100, zone_multiplier=10),
    target_hit_probability=0.865,   # 実機の自力当選率
    ceiling_games=800,
)

hazard_ceiling_ev(hazard, 800, current_games=270,
                  average_payout=600, ceiling_payout=900, net_loss_per_game=2.0)
hazard_breakeven_start_games(hazard, 800, 600, 900, 2.0)
```

ハザードは関数でも、1ゲームごとの確率を並べた配列でも渡せる。ゾーン狙いの機種を扱うなら
`ceiling_ev` ではなくこちらを使うこと。

## 注意

計算はあくまで理論値。分散が大きいので、期待値プラスでも短期では普通に負ける。
資金管理の範囲内で使うこと。
